# Court Semantic Search

Сервис для семантического поиска судебной практики по описанию фактической ситуации.

## MVP

Пользователь описывает кейс естественным языком. Система:

1. анализирует запрос и выделяет факты и юридические концепции;
2. генерирует несколько поисковых формулировок;
3. получает кандидатов через API RAS;
4. извлекает текст судебных актов;
5. выполняет семантический reranking;
6. группирует документы по номеру дела и обогащает данные через KAD;
7. выбирает наиболее содержательный судебный акт;
8. формирует summary, обстоятельства дела и позиции сторон.

После группировки дело можно передать в `POST /api/cases/extract-preferred-text`.
Endpoint скачивает и извлекает текст только из `preferred_document`, выбранного
эвристикой, и возвращает текст вместе с метаданными акта.

## Поиск по описанию

`POST /api/cases/semantic-search` принимает описание ситуации и ищет судебные акты
по нескольким формулировкам через настроенный CourtProvider. Отдельный LLM-адаптер
генерирует `queries`, `must_have` и `exclude`.
Результат содержит найденные дела, исходные `document_id`, `case_id`, `file_url`
и `matched_queries`. Запросы выполняются при каждом вызове; база данных не нужна.

По умолчанию используется локальная Ollama: установите Ollama, выполните
`ollama pull qwen3:4b`, настройте `COURT_PROVIDER` и ключ судебного провайдера,
затем запустите `uvicorn backend.app.main:app --reload`. Локальный API Ollama
не требует оплаты и не зависит от региона, но модель требует ресурсов компьютера.

Для Yandex AI Studio установите `LLM_PROVIDER=yandex`, `YANDEX_API_KEY` и
`YANDEX_FOLDER_ID`. Этот вариант требует платежного аккаунта; стартовый грант
для новых клиентов ограничен сроком и суммой, поэтому не является бессрочно
бесплатным API.

```json
POST /api/cases/semantic-search
{
  "description": "После присоединения заемщика компания учитывала проценты по займу и убытки, налоговая оспорила выгоду",
  "max_pages_per_query": 1
}
```

Этот endpoint возвращает кандидатов из поиска, а не подтверждение соответствия
схеме. `must_have` и `exclude` пока доступны клиенту как признаки для следующего
этапа проверки по тексту PDF. При использовании облачного провайдера перед
отправкой описания удаляйте конфиденциальные сведения.

## Архитектура

```text
Frontend (Next.js)
        |
        v
Backend API (FastAPI)
        |
        +--> Query Analyzer / Query Generator
        |
        +--> Court Provider
        |      +--> RAS API
        |      +--> KAD API
        |
        +--> PDF/Text Extraction
        |
        +--> Semantic Reranker
        |
        +--> Case Grouper / Instance Ranker
        |
        +--> LLM Case Analyzer
```

## Структура

```text
backend/   FastAPI и AI/search pipeline
frontend/  Next.js интерфейс
```

Внешние источники судебных данных подключаются через provider-адаптеры, чтобы можно было переключаться между Parser API и API-CLOUD без изменения основной логики приложения.

## Статус

Проект находится на этапе создания MVP. Доступы к RAS/KAD API ожидаются, поэтому сначала используется MockProvider.
